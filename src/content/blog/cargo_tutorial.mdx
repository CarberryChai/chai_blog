## 写在前面

很多 Rust 教程一上来就让你敲 `cargo new hello`，然后跟着打一遍代码，项目就跑起来了。一切看起来很顺滑，但你其实并不清楚 Cargo 在背后替你做了什么，也不理解为什么 Rust 非要有它。

这一篇我们先不急着写代码。先回答两个问题：**Cargo 是什么？它到底解决了什么问题？** 把这两个问题想清楚，后面学什么都顺。

## 从 rustc 说起

在 Rust 中，一个库或者可执行程序被称为 **crate**（箱子），它由 Rust 编译器 `rustc` 编译。你接触到的第一个 Rust 程序，通常就是经典的 "Hello, world!"：

```rust
fn main() {
    println!("Hello, world!");
}
```

不用 Cargo，直接用 `rustc` 也能编译它：

```console
$ rustc hello.rs
$ ./hello
Hello, world!
```

看起来很直白，但注意一个细节：上面这条命令里，你必须**显式指定文件名** `hello.rs`。这意味着每编译一个不同的程序，你都需要写一条不同的命令。如果你还要加上编译参数、链接外部库，命令会变得更加具体、更加复杂，也更容易出错。

## 真正的麻烦：依赖

更棘手的问题是依赖。

任何一个稍微正经一点的项目，都会用到外部库。而外部库通常还会依赖别的库，于是你的程序就**传递依赖**了它们的依赖。想象一下：你需要手工去获取所有依赖的正确版本，还要在它们更新后手动跟进，这既困难又容易出错，堪称噩梦。

而且这还不是一次性的工作——依赖的版本会变，安全补丁会发布，API 会升级，靠手工维护一套依赖清单，基本上是不可持续的。

## 引入 Cargo

为了解决上面的问题，Rust 在 crate 和 `rustc` 之上，引入了一个更高层的抽象——**package（包）**，以及配套的**包管理器（package manager）**。

**Cargo 就是 Rust 的包管理器。** 它让 Rust 的包可以声明自己的各种依赖，并确保你**永远得到可重复的构建**（repeatable build）——也就是说，无论在哪台机器、哪个时间构建，结果都是一致的、可预期的。

## Cargo 具体做什么

为了达成这个目标，Cargo 做了四件事：

1. **引入两个元数据文件**：`Cargo.toml` 和 `Cargo.lock`。前者描述包的元信息和依赖声明，后者锁定所有依赖的精确版本，保证构建可重复。
2. **拉取并构建依赖**：你声明了哪些依赖，Cargo 就自动帮你从 registry（注册表，比如 crates.io）把它们下载下来，并处理好它们之间的依赖关系。
3. **以正确的参数调用构建工具**：不再需要你手工拼 `rustc` 命令行，Cargo 会替你构造出正确的那一条，并在构建时把依赖安排进去。
4. **引入一系列约定**：让使用 Rust 包变得更简单、更一致。

## 统一的工作流

前三点是能力，第四点是 Cargo 最大的价值所在——**它把命令标准化了**。

回想一下前面 `rustc hello.rs` 的问题：每编译一个程序，命令都不一样。而有了 Cargo 之后，不管你的项目叫什么名字、是一个库还是一个可执行程序，构建命令都是同一条：

```console
$ cargo build
```

你不需要知道 `rustc` 内部需要哪些参数，Cargo 会帮你搞定；你也不需要手动去下载依赖，Cargo 会自动从 registry 拉取并把它们加进构建。

所以有一种说法：**你只需要学会构建一个 Cargo 项目，就等于学会了构建所有 Cargo 项目。** 这一点都不夸张。

## 小结

Cargo 存在的意义，就是把 Rust 项目从"手工编译 + 手工管理依赖"的混乱状态，变成"声明依赖 + 统一命令 + 可重复构建"的工程化状态。它是 Rust 生态体验如此顺畅的基石。

了解了 Cargo 是什么、解决了什么问题之后，下一步我们来实际动手：安装 Cargo，创建第一个项目，看看它的目录结构和 `Cargo.toml` 长什么样。
